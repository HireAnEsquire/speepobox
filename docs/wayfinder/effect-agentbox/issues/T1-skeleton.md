# T1 — Package skeleton: layout, toolchain, config module, `doctor`

Status: done
Type: AFK
Blocked by:

Sequence: [ticket 08](../08-in-hae-sequence.md). First of six tracer bullets.

**Tracer: `doctor` runs green under plain `node`** — no bundler, no transpile step, no `tsx`. That is
this bullet's whole point and it is not cosmetic: ticket 01's clone-run shim executes the TS source
directly under Node's stable type stripping, so an import shape that needs a transform kills the
distribution model. `vitest` transforms, so the test suite cannot catch this; only running the real
binary can.

## What to build

A self-contained top-level package at **`speepobox/`** with no hae workspace coupling — its own
`package.json`, tsconfig, lint/format config, and test runner, so `git filter-repo` can lift it out
later (ticket 04).

### 1. Layout

```
speepobox/
  package.json
  tsconfig.json
  .oxlintrc.json
  .oxfmtrc.json
  AGENTS.md              <- pre-seeded, do not rewrite (see "Already on the branch")
  ISSUE_TEMPLATE.md      <- pre-seeded, do not rewrite
  src/
    bin.ts               <- CLI entrypoint; NodeRuntime.runMain
    config/              <- AgentboxConfig tag + schema + provider chain
    internal/exec.ts     <- the subprocess chokepoint (see §5)
    doctor/              <- probes + renderer
  test/
```

| `typescript` | `7` | 06 |

- `"engines": { "node": ">=26" }` — 04 pinned node 26 to match hae CI, which is what makes incubation

- Package manager is **npm**. The committed `package-lock.json` is a *shipped artifact* — ticket 01's

  regenerated by another package manager.
- Package name `@hireanesquire/bessemer`, bin `bessemer` (ticket 07).

### 3. `npm run verify` — the gate

One script. Ticket 06 requires it to exist and to be the single thing an issue names:

```
"verify": "npm run typecheck && npm run lint && npm run test"
```

- **`typecheck`** runs `tsc` with `@effect/tsgo` patched in, so Effect diagnostics arrive as ordinary
  TS diagnostics on the **single** typecheck. Configure so that **errors and warnings both break the
  build, suggestions print**. Errors-only is not acceptable — it would let `scopeInLayerEffect`
  (silently dropped finalizers) through, which is exactly the class of bug this port exists to
  eliminate. Ticket 11 confirmed Effect's own repo uses this arrangement: `@effect/tsgo` sits in the
  typecheck path, never in the lint path.
- **`lint`** runs `oxlint` then `oxfmt --check`. **Do not enable `typeAware`/`typeCheck`** — 06
  declined the oxlint bridge (one typecheck, one config), Effect's own repo leaves it off, and
  type-aware rules sit outside oxc's semver policy.
- **`test`** runs `vitest`.

`.oxlintrc.json` and `.oxfmtrc.json` are standalone. Nothing needs excluding or scoping: the served
repo's own oxc configs live in a subdirectory, not at the repo root, and both tools resolve config
per-file nearest-wins and never merge into parents (ticket 11).

### 4. Config module

Per **05 Q7 and Q4** — Effect owns sourcing, we own shape:

- A `ConfigProvider` stack expressing the precedence chain **flags > env > local > committed >
  defaults**.
- **One layer decodes it once** into a typed `AgentboxConfig` record, provided as a tag. Do **not** do
  per-call-site `Config` reads: config would then fail deep inside a dispatch instead of at startup,
  and the shape would be written down nowhere.
- Format is **TOML** via `@effect/cli`'s `ConfigFile`: `config.toml` committed,
  `config.local.toml` gitignored, local wins.
- The committed layer carries ticket 01's pinned tool SHA — it must travel with the repo.
- **Runtime-root default (05 Q19): point it at the package's own root, not `.agentbox/`.** During
  incubation two dispatchers live on one host, both resolving repo root to hae; two tools writing one
  lock directory with different staleness rules is a data race. This is a default flipped at
  switchover, not a structural cost. `status` showing half the world during incubation is accepted.

### 5. The subprocess chokepoint

Per **05 Q3** — one file, `src/internal/exec.ts`, is the **only** place allowed to import `Command`. It
is an internal module, **not a tag**: a tag here would recreate the `Shell.exec` anti-pattern that makes
Layer-based testing worthless.

It sets `shell: false` and **`extendEnv: false` with an explicit allowlist**. The default inherits
`process.env` and would leak the parent environment into agent containers — this is a security
property, not a tidiness one.

Add the CI/lint grep bans now, while there is nothing to fix: `Command` imported outside
`internal/exec.ts`, `Command.runInShell`, and `Effect.runPromise`. `NodeRuntime.runMain` is the only
entrypoint idiom.

### 6. `doctor`

Port `run.sh:303-420` — nine probes in dependency order, each a distinct effect with a **typed**
failure, rendered by a thin CLI. This is the first `Layer` exercise and the shape every later command
copies. Exit 1 on any FAIL, exit 0 on warnings.

`doctor` is one of three read-only commands intercepted **before** flag parsing and before any
preflight, deliberately, because they must work when the thing they inspect is broken (03 §1.1). So its
probes call the chokepoint directly; they do **not** go through `Sandbox` (introduced in T3).

Probes, adjusted for the port:

| # | Probe | Change from bash |
| --- | --- | --- |
| 1 | docker CLI present + daemon reachable | as-is |
| 2 | image present + staleness | as-is |
| 3 | credential presence — LLM API credential only, **presence reported, never the value** | as-is |
| 4 | **host `node` ≥ 26** | replaces "host python ≥ 3.14" |
| 5 | git work tree + `origin` present | as-is |
| 6 | `gh` present + authenticated | as-is |
| 7 | **config decodes** — `config.toml` parses and satisfies the schema | new; makes §4's decode-once failure visible before a dispatch |
| 8 | spec/tasks dir present | as-is |
| 9 | **runtime root writable** | new; the 05 Q19 root, checked because it is a fresh default |

**Dropped: the `gum` and `fzf` probes.** 05 replaced both with clack — `autocomplete` closes the fuzzy
gap, so there is no external prompt binary to check for. (`fzf` was already conditional in bash, probed
only if `tasklib.py` still grepped for it.)

## Effect wiring

- **Tags introduced**: `AgentboxConfig`, `Reporter`.
- **Not introduced here**: `Sandbox`, `Git`, `Forge`, `AgentCli`, `Ledger`, `IssueStore`, `Notifier`,
  `RunLock`, `PromptSource`, `Prompt`. Do not stub them.
- **Layer composition**: one `AppLive` layer wired at the entrypoint and provided to every subcommand,
  with services acquired lazily inside their own scoped constructors (05 Q21). Per-subcommand layers
  were rejected — they multiply the `provide`-vs-`provideMerge` confusion that is the top LLM failure
  mode in Effect. Paste the `effect-language-service layerinfo` output for `AppLive` into the PR
  description.

## Acceptance criteria

- [ ] `speepobox/` is self-contained — no hae workspace coupling, no import crossing the package
      boundary in either direction
- [ ] `npm run verify` passes, and each of typecheck / lint / test genuinely runs against `src/`
      (verify by breaking one thing at a time and watching the right step fail — a green that checks
      nothing is the specific failure mode 06 named)
- [ ] Typecheck fails the build on an Effect **warning**, not only on an error. Demonstrate with a
      temporary `scopeInLayerEffect` case, then remove it
- [ ] `oxlint` runs with `typeAware` off; `oxfmt` pinned exact
- [ ] `AgentboxConfig` is decoded once by one layer and provided as a tag; no per-call-site `Config`
      reads exist
- [ ] Precedence chain flags > env > local > committed > defaults is covered by tests using
      `Layer.succeed` over an object literal
- [ ] The runtime-root default points at the package's own root, **not** `.agentbox/`
- [ ] `Command` is imported in exactly one file; `runInShell` and `Effect.runPromise` appear nowhere;
      the grep bans are wired into `verify` or CI
- [ ] `exec` sets `shell: false` and `extendEnv: false` with an explicit env allowlist
- [ ] `doctor` implements the nine probes above, each with a typed failure, exit 1 on FAIL and 0 on
      warnings; credential probes report presence only, never a value
- [ ] **`doctor` runs green under plain `node` with no transform step**, and this is what the PR
      description demonstrates

- `node src/bin.ts doctor` — nine rows in dependency order. The two FAIL rows (`credential`,

  majors behind the `>= 26` floor

**Post-review fix (`a7a414fd91`).** `doctor` read `process.versions.node` directly, so all five
doctor outcome tests reported on whichever node ran vitest — green in the node 26 container, red
on a node 23 host. `doctor` now takes `hostNodeVersion` and `bin.ts` supplies it, plus an
outcome-row test for the below-26 path. Worth carrying: the container satisfies every
prerequisite by construction, so the gate cannot see a host-dependent test. Host reads belong at
the composition root.

**Inherited by later bullets.** The `>= 26` host floor is asserted, not evidenced — the package
ran end-to-end on node 23.7, and the only node builtins in `src/` are `node:path`, `node:url`,
`node:fs`. It was chosen because node 26 deleted `--experimental-transform-types` (ADR 0007) and
to match hae CI, not for an API. `erasableSyntaxOnly` is the real constraint and holds at any
floor, so if an LTS-pinned adopter ever appears, lowering it is two constants: `nodeMajor(version)
>= 26` in `probes.ts` and `engines` in `package.json`.
